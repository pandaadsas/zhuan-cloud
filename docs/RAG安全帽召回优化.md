# 安全帽问题召回诊断与优化

2026-10-02，使用仓库原规范、固定合成问题、临时 SQLite 与 Chroma 目录进行真实 embedding 对比。没有读取业务记录或调用文本模型。

## 诊断结论

“工人在工地干活时必须戴安全帽吗”、中性查询“施工现场 作业人员 安全帽 佩戴要求”、日志中的“进入施工现场必须佩戴安全帽 个人防护用品 要求”，三者的向量 Top-10 均没有第 3.2.1 条。因此本轮采用关键词补召回，不仅重排现有十条。

第 3.2.1 条明确涵盖高处作业人员正确佩戴安全帽、安全带的要求，不能据此概括所有施工情形。该诊断条款是相关条款标注，不是原问题的充分支持标注。

## 实现

- 精确编号入口保持优先；不存在的编号不回退。
- 正常查询取向量至少 Top-10，同时对内存条款标题和完整正文做本地 BM25 检索。中文使用连续二字片段，英文和数字使用完整词，不引入分词库、手写安全帽词表或特定条款提升规则。
- 合并保留向量第一条，接着补入 BM25 前两条，再按向量优先补齐。按规范名、条款号和正文去重，最终仍只返回 k 条。助手 k=3、上报 k=4；十条候选不会全部进入回答上下文。
- `mode=hybrid` 表示成功使用真实向量并有本地关键词候选。融合 score 是两通道 `1/(60+rank)` 之和，仅用于诊断；实际顺序按上述通道配额决定，不用不同检索器原始分数互相比较，也不作为拒答门槛。
- 向量失败或无结果仍使用原字符降级；未找到关键词候选时保持纯向量结果。
- 查询工具说明要求保持疑问原意、核心对象、数字、否定及适用条件，避免扩大范围或用宽泛词替代对象。
- 核验日志增加 reason 和 unsupported_points；不修改核验提示词、接受条件及引用校验。

最初只补 BM25 第一条时，日志中的宽泛改写仍遗漏第 3.2.1 条；补前两条后才覆盖该样例。这是针对已知失败样例的开发调整，不能当作独立盲测。

## 结果

| 查询 | 优化前第3.2.1条排名 | 优化后排名 |
|---|---|---|
| 用户原问题 | Top-10 外 | 2 |
| 中性关键词 | Top-10 外 | 2 |
| 日志中的改写 | Top-10 外 | 3 |

原有 40 条回归集：上报 20 条 Recall@4=1.0、MRR=1.0；问答 10 条 Recall@3=1.0、MRR=1.0，均与优化前相同。5 条编号样例结果不变，包括不存在编号返回空；5 条库外问题仍有候选召回，仍需下游核验，不宣称解决拒答问题。共 46 项 unittest 测试通过。

原始报告见 [优化前](RAG安全帽优化前诊断.json)、[优化后](RAG安全帽优化后诊断.json)。两份报告的 `candidate_query` 使用线上上报查询构造方式；原有40条应与追加的3条诊断样例分开计算。各变体复用 query embedding，耗时不是独立冷请求延迟基准。
