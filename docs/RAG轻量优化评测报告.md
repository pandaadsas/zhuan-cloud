# RAG 轻量优化评测报告

评测日期：2026-10-02（Asia/Shanghai）。默认向量模型：`text-embedding-v4`。真实向量评测已完成，没有发生字符降级。逐条结果见 [RAG轻量优化评测.json](RAG轻量优化评测.json)。

## 方法与验收决定

固定样例 40 条：上报 20、规范问答 10、编号查询 5、知识库外问题 5。条款标注由实现者核对仓库规范原文，未经过领域专家独立复核；这是回归集，不能证明在真实用户问题上的泛化效果。上报使用固定抽取字段，不评估信息抽取模型。

三组使用同一语料、模型和索引：`baseline` 冻结原 search 行为；`optimized_raw` 加入编号精确匹配但保留原始上报文本；`candidate_query` 再加入上报查询优化。上报按 Top-4、其他查询按 Top-3 评估。Recall 为每条样例相关条款覆盖率的均值；MRR 为首个相关条款倒数排名的均值。不存在编号单独按负例统计，不参与正例均值。

真实向量上报 Recall@4 保持 1.000，MRR 从 0.975 提升到 1.000，通过“Recall、MRR 不下降且至少一项提高”的门槛；字符模式两项均持平。因此启用 `REPORT_QUERY_OPTIMIZATION_ENABLED`。若更换模型或扩大知识库，应重新评测；关闭该常量可恢复原始上报查询。

## 生成上下文与测试

取消正文前 80 字截断，前三条规范按 8,000 字符预算完整纳入；超预算条款整体跳过。测试使用真实第3.10.5条，验证第80字之后的“严禁预约停送电”等要求进入 LLM 上下文，而不是仅检查字符串长度。未运行生成模型的答案质量评测，因此此项只确认输入信息完整性。

19 项 unittest 全部通过，包括既有聊天操作确认协议、精确编号、降级、查询事实保留、查询开关、完整条款预算、评测指标和真实模式失败停止逻辑。现有聊天测试仍出现 SQLite 连接 ResourceWarning，不影响通过结果。

## 失败样例与下一阶段

- **混合检索候选**：字符模式 H01（临边护栏被拆除）未召回第3.2.3条，Top-10 也未命中；属于术语/语义漏召回。真实向量模式该样例通过，因此尚不足以证明必须增加混合检索。
- **Rerank 候选**：本次优化后正例没有“正确条款位于 Top-10 但没进入 Top-K”的失败样例；当前不新增 rerank。
- **拒答校准候选**：字符模式 O02、O04、O05 错误命中；向量模式 O01～O05 全部错误命中。这里统计的是检索返回无关条款，未评估生成模型是否拒答。下一阶段应扩大负例集并校准相关性/拒答策略；本轮不设任意相似度阈值。

## 复现

在 `backend` 目录执行：

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe scripts/evaluate_rag.py --mode keyword --output ../docs/RAG轻量优化评测.json
# 已启用真实 AI、配置 Key 且允许发送固定样例与规范文本到 DashScope 时：
.venv/Scripts/python.exe scripts/evaluate_rag.py --mode both --output ../docs/RAG轻量优化评测.json
```

脚本只读取环境变量和 `backend/.env` 的模型配置，不读取业务数据库或设置页配置。临时索引位于随机生成的 `backend/.rag-eval-*` 目录，用后清理；向量配置缺失或同步/查询降级时输出 `unverified`，不会把字符结果记为真实向量验收通过。单模式运行会覆盖指定报告，保留完整对比时使用 `--mode both` 或另选输出路径。
