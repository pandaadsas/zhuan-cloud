## 1. 背景与场景

### 1.1 目标用户

筑安云面向房屋建筑工程施工现场的参建各方，核心用户为：

- **安全员（主要使用者）**：25~45岁，每日巡检现场，习惯手机拍照、微信语音，数字化水平中等，是隐患上报与整改验收的一线执行者；
- **分包责任人/班组长**：30~55岁，接收整改任务并组织工人落实，多数只熟悉微信等基础应用，需要极简的任务接收与反馈界面；
- **安全总监**：35~50岁，负责重大风险研判与安全例会，需要看板、周报等决策型界面；
- **项目经理**：35~55岁，项目统筹与对上汇报，关注整改率、超期与风险趋势。

系统按角色呈现不同的工作台界面：安全员是"上报+审核"工作台，分包责任人是"我的整改任务"工作台，安全总监与项目经理是"看板+周报"决策台，界面和权限随角色自动切换。

### 1.2 用户痛点与问题定义

施工项目安全隐患治理长期存在"三难"：

1. **上报流转慢**：安全员发现隐患后，需要口头告知或电话联系分包，再线下填写检查记录、整改通知单，纸质单据逐级签字，从发现到责任班组收到整改要求往往过去数小时甚至隔天；
2. **责任不清晰**：一个项目十几家分包交叉作业，临边防护归主体劳务、动火作业归机电、消防通道归环境分包，出了问题"谁都管、谁都不管"，整改互相推诿；
3. **流程闭环难、复盘靠手工**：整改是否完成、复查是否合格、哪些工单超期，散落在微信群和纸质记录里；每周安全例会前，安全员要手工翻记录汇总周报，耗时2~3小时还容易漏项。

现有信息化工具（传统安全管理系统）主要解决"电子化填表"，录入仍靠人工逐项填写，没有解决"上报麻烦、判断困难、责任难定"的本质问题。要解决的核心问题是：**让隐患从发现到闭环的全流程，由AI自动流转、自动判断、自动留痕，人只做确认和决策**。

### 1.3 使用场景

**场景一（日常巡检）**：安全员张明巡查至3号楼12层，发现东侧临边防护栏杆缺失。他打开筑安云拍照上传并补一句语音描述，AI自动识别出"高处作业-临边防护"、定级高风险、检索出知识库中的相关防护条款并给出处置建议，同时根据责任分区自动匹配到恒盛劳务赵强。张明确认后一键派单，赵强登录后查看工单，整改完成后拍照提交，张明复查合格闭环——按实际整改与复查进度完成，每一步留痕。

**场景二（周例会前）**：周五下午，安全总监李强在AI助手里输入"生成安全周报"，系统按风险等级自动汇总本周隐患数量、整改进展、超期工单和重点关注项，生成带规范依据的周报并导出Word，直接用于周例会与对上汇报。

### 1.4 价值体现

- **效率提升**：隐患从发现到派单减少重复填报与流转等待；周报自动聚合工单数据，并可一键导出Word；
- **责任压实**：AI按"位置+隐患类型"自动匹配责任分包与责任人，派单到人，便于跟进；
- **风险受控**：重大风险工单强制安全总监复核，超期工单自动红色预警并进入督办清单，风险闭环有抓手；
- **决策有据**：处置建议展示检索到的规范条款出处，周报基于真实工单数据，不编造数字；
- **管理留痕**：工单全生命周期写入流转日志，便于过程复盘与资料核对。

## 2. 功能说明

### 2.1 核心功能

| 功能 | 用户输入 | 处理方式 | 输出结果 | 解决的问题 |
|---|---|---|---|---|
| 多源隐患上报 | 文字/语音/照片（可组合） | 语音经ASR转文字；照片经多模态模型识别隐患并生成描述 | 结构化上报内容 | 现场人员随手报，降低上报门槛 |
| AI工单生成 | 上报文本 | LangGraph流水线：信息抽取→知识检索→风险定级→处置建议 | 含类型、位置、等级、规范依据、整改要求的工单草稿 | 免去人工填单，判断有规范依据 |
| 责任智能匹配 | 工单草稿 | "隐患位置→责任分区"与"隐患类型→分包承包范围"双路匹配 | 推荐责任人+匹配理由+备选 | 责任到人，杜绝推诿 |
| 人工审核派单 | 安全员确认 | 人工在AI草稿上确认/改派；重大风险强制安全总监复核 | 正式工单派发至责任人 | AI建议、人决策，安全兜底 |
| 整改闭环管理 | 责任人操作 | 状态机流转：待审核→已派发→整改中→待复查→已闭环/已驳回，支持延期与退回 | 全流程流转日志+整改照片 | 过程留痕、闭环可查 |
| 超期预警 | 系统自动 | 按风险等级设定整改期限（重大24h/高48h/中72h/低7天），到期未闭环自动标红 | 看板督办清单 | 超期无处藏身 |
| AI安全助手 | 自然语言提问或明确上报指令 | 9工具Agent：进度、筛选、统计、规范、周报生成/列表/全文、目录、上报 | 回答、引用和业务卡片 | 对话查询与待审核建单 |
| 项目管理助手 | 项目经理提出管理需求 | 11工具管理项目、区域、分包和负责人目录；写操作先预览确认 | 目录结果、确认卡片与执行结果 | 降低资料维护成本 |
| 聊天工作区 | 新对话或历史续聊 | 服务端保存正文、轨迹、引用和卡片，按用户/项目/助手隔离 | 历史恢复、复制、重试、移动端抽屉 | 保留上下文与操作结果 |
| 安全看板 | 打开页面 | 单查询聚合统计 | 趋势图、风险分布、类型Top6、超期督办表 | 项目安全态势一屏掌握 |

### 2.2 技术方案

**整体流程**：用户输入（文字/语音/照片）后，系统先做多模态归一（语音经通义ASR转写、照片经通义视觉模型描述），再由 LangGraph 编排的隐患处置流水线依次完成：①信息抽取Agent——大模型按JSON Schema抽取楼号、楼层、部位、隐患类型并初判风险（信息不足时自动追问）；②规范检索Agent——以向量化语义检索从安全知识库召回相关条款；③风险定级与处置建议——结合类型底线规则与召回条款生成建议，引用条款出处；④责任匹配——查询项目责任分区矩阵与分包承包范围；⑤生成待审核工单草稿。人工审核通过后由任务派发模块下发，后续整改、复查、闭环均由状态机驱动并写入流转日志；超期自动预警，周报按风险等级聚合生成。

**AI智能体架构**：隐患上报采用LangGraph固定流水线，负责抽取、追问分支、检索、定级建议、责任匹配和草稿组装；审核、整改和复查由REST工单状态机与人工操作完成。对话采用独立的通义千问tool-calling循环，最多5轮，通过助手画像选择安全9工具或项目管理11工具，不由LangGraph编排对话。REST上报和对话上报共用 `services/reporting.py` 落库逻辑。

**提示词与交互设计**：为抽取、建议、周报、问答分别设计了角色化提示词；抽取采用JSON输出约束与枚举类型表保证结构稳定；问答要求"标注条款出处、检索不到明确说明"，抑制编造；隐患工单以待审核草稿呈现，派单需人工审核。项目管理写操作以字段预览卡呈现，token绑定用户与项目、10分钟有效，必须点击确认按钮后执行；自然语言中的“确认”不会执行已有操作。只读查询直接返回结果，生成周报会保存周报。

**知识库**：当前内置源文件是《建筑与市政施工现场安全卫生与职业健康通用规范》Markdown。启动时按编号条款切片，以 `source=builtin` 幂等同步至Regulation表，替代旧版49条种子库；每条保留文档名、条款号、标题、正文和确定性标签。向量存入Chroma本地持久化库，按内容哈希增量更新，集合按embedding模型隔离；模拟或失败时回退bigram Jaccard。当前未实现来源优先级排序、rerank或通用上传导入，条款数量以源文件解析结果为准。

**工作流与工具调用**：采用 LangGraph StateGraph 实现业务状态机，节点可独立替换引擎；系统工具包括：MySQL业务库查询（责任分区/人员/工单）、向量语义检索、邮件服务（注册验证码）、通义多模态调用（图片识别/语音转写）、Word文档生成。

**自主开发说明**：本作品为全自主开发。前端采用 Vue3 + Element Plus + ECharts（四角色工作台、AI对话、数据看板）；后端采用 Python FastAPI + SQLAlchemy 2.0；数据库为 MySQL优先、不可达回退SQLite（14张表，包含项目、业务记录、验证码、运行时配置、会话、消息和待确认操作）；向量检索采用通义 text-embedding-v4 + Chroma HNSW（cosine Top-K召回）；AI能力统一接入通义千问（qwen-flash 文本 / qwen-vl-plus 图片 / ASR 语音 / text-embedding-v4 向量）。系统设计了**双引擎模式**：内置模拟引擎可演示上报闭环与安全助手四类规则问答（零API消耗）；完整工具对话和项目管理助手依赖真实AI，配置密钥后一键切换真实大模型；部署方式支持本地运行与服务器部署（Systemd/云端MySQL）。

### 2.4 创新与差异化

1. **可解释、可审计的Agent工作流**：不同于"黑盒对话"，处置流程是显式状态机，每个节点（抽取引擎、召回条款、匹配理由）全部展示给用户，可回溯、可追责；
2. **规范条款可溯源**：处置建议展示召回条款的出处，便于核对；风险定级另由抽取结果、类型底线与重大关键词取高决定，引用不是合规认证；
3. **Human-in-the-loop 安全兜底**：AI生成草稿、人工确认派单；重大风险工单强制升级安全总监复核——把"AI会不会乱派单"的行业顾虑变成产品机制；
4. **责任矩阵自动匹配**：以"楼栋分区×分包承包范围×责任人"三维矩阵自动定位责任人，并给出匹配理由与备选人；
5. **双引擎设计**：模拟引擎与真实大模型一键切换，演示零成本、现场断网不翻车，配置密钥后使用真实AI能力；
6. **多模态+多角色协同**：语音、照片、文字三路上报，四角色界面与权限随角色自动切换。
7. **工具对话与写入确认**：双助手按职责隔离，查询结果以业务卡片呈现；项目管理写操作先核对字段再确认执行，历史会话保留结果。

### 2.5 作品完成度

**已完成**：四角色工作台与权限体系；多源上报（文字/语音/图片）与AI工单生成；责任智能匹配与人工审核派单；整改状态机闭环（含整改照片提交、退回、延期）；超期自动预警与督办清单；ECharts安全看板；安全9工具与项目管理11工具助手、服务端会话恢复、结果卡片及项目管理写入确认；按风险等级AI周报与Word导出；邮箱验证码注册登录；规范Markdown切片入库与Chroma增量向量检索；通义千问真实AI接入与内置模拟双引擎；聊天协议与确认操作自动化测试（`backend/tests/test_chat_protocol.py`），运行方式见README；远程模型效果需真实配置下验证。

**存在不足**：手机号短信注册通道尚未开通（接口已预留，需短信服务审批）；语音转写在真实模式下依赖ASR模型开通情况；界面以桌面浏览器为主，移动端为响应式适配而非独立App；演示项目数据（分包、人员、制度）为基于公开项目提炼的合理虚构。

**后续优化方向**：接入项目IoT/视频监控实现自动巡检上报；增加统计分析与隐患趋势预测；小程序端与消息推送（工单到达即时提醒）；在现有多项目上下文基础上完善组织与成员授权、消息通知和检索精排。
