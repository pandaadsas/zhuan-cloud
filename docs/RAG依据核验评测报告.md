# RAG相关性与依据核验评测报告

2026-10-02。本轮已接入安全助手和隐患上报，并完成约定的真实向量验收。当前项目 `.env` 已设置 `RAG_EVIDENCE_CHECK_ENABLED=true`，新进程读取配置确认已开启；运行中的后端需重启或触发代码重载后生效。代码及 `.env.example` 的新环境默认值仍为false，新配置需先验收。没有数据库迁移、第三方依赖、混合检索或rerank。

## 实现

共享模块为 `backend/app/rag/evidence.py`。检索仅产生候选，核验检查原始问题的全部子问题、数字、条件与禁止事项。安全助手最多三条候选，上报四条；规范名、编号、标题和完整正文共用8,000字符预算，超预算整体跳过并记录日志，不能认定完整覆盖。助手另传最近两轮历史、最多4,000字符及独立检索query，历史不是证据；上报使用原始描述。

核验使用当前文本模型，关闭思考模式，要求JSON；SDK连接/读取超时及整体等待时限均为20秒，`max_retries=0`。每次检索最多尝试一次核验。整体时限防止持续网络读取导致等待超长，过期响应不会进入业务结果；它不保证上游请求立即取消。JSON结构、候选ID集合、引用与证据一致性、正文连续摘录均在本地验证，空白差异允许归一化；至少8字符或整条短正文，不接受拼接、省略改写、标题证据或伪造摘录。异常统一返回unverified，不能解释为规范不存在。

仅完整匹配纯编号原文查询时直接返回条款，解释和复合问题仍核验。编号命中的1.0不作为依据充分性的分数。`search()`字段不变。

| 状态 | 安全助手 | 隐患上报 |
|---|---|---|
| supported | 仅将接受条款、支持要点和对应候选ID交给生成；移除相似度 | 仅接受条款进入建议和工单引用 |
| partial | 回答支持部分，列出缺少依据部分 | 引用只覆盖支持部分，其他要求标明待核实 |
| insufficient | 固定说明当前知识库依据不足，引用为空 | 一般处置模板、待人工核实提示、无引用草稿 |
| unverified | 完整候选原文及未经核验提示，不生成规范结论，引用为空 | 一般处置模板、待人工核实提示、无引用草稿 |

Agent和规则降级共享结果。规范工具前的模型文字替换为进度；本报告评测时首次未调用工具直接回答会补做一次规范检索。该兜底现已被明确的模型路由出口取代，见 [RAG路由优化说明](RAG路由优化说明.md)；本报告原有核验结果不代表新路由已验收。连续工具调用后失败会清空旧的确认引用。现有SSE事件及工单字段保留；卡片增加可选status、notice、candidates，失败卡片标题为“候选条款”，旧卡片兼容。风险底线、责任匹配、期限和审核流程不变。已通过核验但建议生成失败时，使用一般模板并单独列出已核验依据和缺失提示。

## 样例与复核

固定样例见 `backend/tests/fixtures/relevance_cases.py`：80条问答（充分支持、完全无关、主题相关但缺依据、部分支持各20条），开发与验收各40条、每类10条。20个支持问题族的支持/部分版本放在同一集合，其余问题族独立，不跨集合。另12条固定上报，四种状态各三条，故障案例明确注入TimeoutError。

标注在提示词调整前固定，支持条款与缺失要点逐条对照整份仓库规范；本次由Codex实现侧核对，不是独立人工或领域专家复核。每条记录该状态，尚未进行领域专家复核。语义复核由实现侧对照全文、证据与答案逐条记录，不使用被测Qwen判断模型自评分；同样不能视为独立人工复核。

标准答案仅用于本地评分，没有传给检索、核验或回答模型。评测导入连接隔离，使用内存SQLite与临时Chroma目录，配置只读环境变量/`.env`，不读取业务记录。语义复核文件绑定具体报告SHA256、样例及核验提示词版本；缺少逐条复核不能开启验收门槛。`--remote`才允许外部模型调用；本地模拟结果明确标记unverified。

## 实测

模型：`qwen3.8-flash`、`text-embedding-v4`。语料SHA256：`d4b04c7bd8cff870ad90b0617b36c3d3dd0dd3bab3942b7f29d04d79ef751c62`。核验提示词SHA256：`c4b1de3882576cac9ec75b7c64fc0ce97efcd0909808788ac1e83c25fc677980`。完整版本信息见JSON。

| 验收项 | 结果 | 门槛 |
|---|---:|---:|
| 实际检索模式 | 问答40/40、上报12/12为vector | 不能以字符模式替代 |
| 20条无依据问题误接受 | 0 | ≤1 |

| 10条部分支持保留支持并说明缺失 | 9 | ≥9 |

| 依据核验尝试 | 问答40次，上报12次 | 每次检索最多一次；其中上报3次为注入失败 |

验收失败样例是S18和P19：模型返回`candiate_id`/`candidat_id`及`id/text`，缺少要求的`candidate_id/quote`，本地校验拒绝。本次没有修复模型字段、重试、修改标注或放宽门槛；助手只展示候选原文。这分别计为一次充分支持未完成、一次部分支持未完成。

开发集最终复测：无依据误接受0/20，充分支持9/10，部分支持10/10，S02因短摘录未通过校验；追加核验平均2.13秒。开发首轮11条无法核验，关闭思考模式后复测为2条，强化连续摘录提示后为1条。开发结果不作为验收集成绩，早期完整记录保留。

基线问答使用原有规范问答提示词、相同候选及模型；优化版本使用共享核验与回答约束。验收基线39条获得答案，逐条核对未发现所问数值/品牌等被补造；M15基线超时，不纳入基线误答率。因此不能宣称本实验降低了已经为0的基线生成误答率。可验证的变化是：20条无依据问题的基线仍携带候选引用，优化后确认引用全部为空，并在代码中统一控制拒答、部分回答及故障展示。代价是两条格式失败使有效回答覆盖下降。

追加核验平均2.22秒，样本P95为3.19秒。问答生成阶段（不含检索）基线平均4.36秒、优化平均4.46秒；无依据/无法核验跳过后续生成，不能简单将新增调用耗时等同于整体耗时差。S11后续生成超时，改为确定性渲染已核验要点。

上报基线10/12生成超时，其前后建议质量比较未充分验证；R04与R07获得基线文本。优化六条有依据案例中R05获得真实建议生成，其余五条生成未完成后使用一般模板与明确的已核验依据段。九条正常上报依据核验均为真实调用；另外三个为故障注入。12条引用和草稿行为已验证，但不能据此宣称六条均完成真实建议生成。上报记录的总耗时包含基线和优化两次执行，不能用作生产上报延迟。

评测中的基线/回答生成另设整体20秒等待上限，避免原有生成网络调用阻塞整轮评测；生产原有生成调用的配置没有因此改变。两次未完成的早期验收执行中断后重跑，未用于评分。最终判断提示词、标签和门槛未据验收输出调优。

## 复现与上线

在backend目录执行：

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe scripts/evaluate_relevance.py --split all --reports --output ../docs/local-relevance.json
.venv/Scripts/python.exe scripts/evaluate_relevance.py --remote --mode vector --split development --output ../docs/development-relevance.json
.venv/Scripts/python.exe scripts/evaluate_relevance.py --remote --mode vector --split acceptance --reports --output ../docs/acceptance-relevance.json
.venv/Scripts/python.exe scripts/evaluate_relevance.py --review-input ../docs/RAG依据核验验收评测.json --review ../docs/RAG依据核验验收语义复核.json --output ../docs/relevance-scored.json
```

新运行需重新逐条复核，并绑定新报告哈希，不能复用旧评分。真实模式缺配置或检索发生降级会标记未验证。脚本会保存问答及逐条上报检查点，执行中状态不能当验收通过。真实Agent完整会话生成未做额外线上端到端验收，其工具/SSE接入由集成测试验证；QA模型评测是共享核验及相同回答约束的独立驱动。

当前模型及语料下已达到本轮门槛，开关在当前环境中开启。回退可设置`RAG_EVIDENCE_CHECK_ENABLED=false`并重启后端，恢复此前链路。换模型、提示词或语料后需重新验收；新环境默认关闭。评测集仅测试使用，线上只运行核验代码和提示词。

80条合成问题规模较小，尚无真实业务分布和领域专家复核；本地只能验证引用/摘录存在，不能证明所有支持要点必然正确，后续生成也可能出错。继续收集误接受、误拒答和部分覆盖失败；精确术语漏召回考虑混合检索，Top-10命中但Top-3/4落后考虑rerank，模式/版本变化须重新校准。本轮没有设置向量分数门槛，未保证通用库外问题拒答已彻底解决。
