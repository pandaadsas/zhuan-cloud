# 安全助手路由优化

用户消息与历史先进入现有 Agent 模型，由模型选择普通回复、追问、业务工具或规范检索。新增 `reply_directly` 和 `ask_clarification` 终端工具，直接输出文本，不追加生成调用，也不发送工具进度或规范卡片。该能力只接入安全助手，项目管理助手保持原协议。

取消“首轮未调用工具就强制检索规范”。安全助手首轮必须选择明确出口；未知工具、非对象参数、错误 JSON、空对话文本、混用对话与业务工具等在输出前被拒绝，交给已有异常降级入口。工具结果后的正常最终文本继续允许。检索工具前仍隐藏未经核验的模型结论。

规范问题的数字、适用性、合规和处置依据仍要求检索并核验；混有问候或要求跳过检索的安全问题也适用。业务工具权限、确认和工单流程保持现有行为。模型的路由判断可能出错，代码验证格式不能证明意图正确，需独立评测漏检索。

模型不可用时，规则链路仅完整匹配基本交流，明确业务问题走业务工具，明确规范主题或三段编号走知识库，其余请求补充信息，不再默认规范检索。移除了“多少”“情况”单独触发统计的宽泛规则，避免防护高度等问题误走统计。降级不能可靠理解所有追问，信息不明时明确提示理解服务不可用。

## 验证记录

2026-10-02：`python -m unittest discover -s tests` 共 43 项通过，覆盖直接回复单次模型调用、历史传递、无引用和无规范卡片、错误路由不执行工具、业务查询不检索、规则降级、原有规范核验、隐患上报及聊天确认协议。新增测试没有模拟模型自行正确理解意图的能力，不能代替真实模型验收。

- 30 条固定路由样例：普通交流、规范、混合/要求绕过检索、业务、缺信息、多轮追问各 5 条。见 `backend/tests/fixtures/routing_cases.py`。
- `backend/scripts/evaluate_routing.py` 对比原提示/原工具集加旧强制检索行为与当前路由。只调用模型选择首轮出口，绝不执行业务工具；配置只读环境设置，导入时使用内存数据库，不读业务记录。标准出口只用于评分。
- 本次真实评测尝试的 60 次请求（前后各 30 次）均失败，连接探测返回 `Connection error`。真实路由准确率和延迟未验证，不能将失败视为模型误路由或通过。扩大网络权限的请求随后被自动审批拒绝，待用户授权发送系统提示、工具定义及合成问题后再运行。
- `RAG路由评测.json` 保留失败请求记录；`RAG路由检索回归.json` 是 40 条字符检索回归，不能代替向量验收。
- `RAG路由核验回归.json` 为 80 条依据样例及 12 条上报案例的无远程调用回归，均按未核验路径处理，仅确认离线路径可以运行，不能作为语义验收。
